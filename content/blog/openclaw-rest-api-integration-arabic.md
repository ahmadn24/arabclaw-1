## المقدمة: لماذا دمج API مع أوبن كلاو؟

وكيل ذكي معزول لا قيمة له. إذا كان وكيلك يتحدث معك فقط ولا يستطيع الوصول إلى بيانات شركتك الحقيقية أو تنفيذ إجراءات في أنظمتك، فأنت تملك روبوتاً زينة وليس أداة عمل.

عندما تدمج REST API مع أوبن كلاو، تحول وكيلك إلى موظف رقمي حقيقي. يمكنه الاتصال بقاعدة بيانات عملائك، التحقق من حالة الطلبات، تحديث سجلات الموارد البشرية، أو إرسال رسائل إلى خدماتك الداخلية. كل هذا يحدث بأمان وفعالية، دون تدخل يدوي.

في هذا المقال، سنتعامل مع الواقع كما هو: لا نصائح نظرية غامضة، بل خطوات حقيقية وأكواد تعمل تستطيع تطبيقها على الفور.

## فهم أساسيات REST API في سياق أوبن كلاو

REST هو نمط معماري قديم وموثوق للتواصل بين التطبيقات. بدلاً من شرح نظري، دعنا نفهم الأنواع الثلاثة الأساسية التي ستحتاجها:

### 1. طلب GET (جلب البيانات)

تستخدمه عندما يحتاج وكيلك إلى قراءة معلومات من نظام آخر، مثل معرفة حالة طلب، أو جلب قائمة المنتجات، أو التحقق من رصيد العميل.

```bash
curl -X GET "https://api.store.com/orders/12345" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

الاستجابة عادة تكون بصيغة JSON تحتوي على البيانات المطلوبة. أوبن كلاو تستقبل هذه البيانات وتعالجها بذكاء للإجابة على أسئلة المستخدم.

### 2. طلب POST (إرسال البيانات وإنشاء سجلات جديدة)

تستخدمه عندما يريد وكيلك إنشاء شيء جديد أو تقديم معلومات. مثلاً، تسجيل عميل جديد في النظام أو إضافة عنصر إلى سلة التسوق.

```bash
curl -X POST "https://api.store.com/customers" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "أحمد السعيد",
    "email": "ahmed@example.com",
    "phone": "+966501234567"
  }'
```

### 3. طلب PUT/PATCH (تحديث البيانات القائمة)

عندما تريد تعديل معلومة موجودة بالفعل. الفرق الدقيق: PUT يستبدل السجل بالكامل، بينما PATCH يحدث الحقول المحددة فقط.

```bash
curl -X PATCH "https://api.store.com/customers/5678" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "نشط",
    "subscription_tier": "متقدم"
  }'
```

## المصادقة: السور الحقيقي بين وكيلك والعالم الخارجي

أي شخص يمكنه إرسال طلب إلى API. المصادقة هي ما يثبت أن وكيلك لديه الحق في ذلك. إليك الطرق الرئيسية:

| طريقة المصادقة | الاستخدام | مستوى الأمان | ملاحظات |
|---|---|---|---|
| API Key (مفتاح API) | خدمات داخلية بسيطة | متوسط | سهلة وسريعة، لكن احفظ المفتاح بحذر |
| Bearer Token | APIs خارجية موثوقة | عالي | تُصدّر من قبل الطرف الآخر، غالباً مع صلاحية زمنية |
| OAuth 2.0 | تطبيقات الطرف الثالث | عالي جداً | معقد لكن آمن جداً، تفويض محدود |
| Basic Auth | أنظمة قديمة | منخفض | تجنبه إن أمكن (يرسل كلمة المرور مشفرة ضعيفاً) |

### كيفية تخزين المفاتيح بأمان

أبداً لا تكتب مفتاح API مباشرة في الكود:

```python
# خطأ كبير
api_key = "sk-1234567890abcdef"

# صحيح
import os
from dotenv import load_dotenv

load_dotenv()
api_key = os.getenv("API_KEY")
```

احفظ المفاتيح في ملف `.env` أو في متغيرات البيئة على خادمك. في أوبن كلاو، تستطيع تخزين المفاتيح في أقسام الأمان الخاصة بالمنصة.

## معالجة الأخطاء والاستجابات غير المتوقعة

ليس كل شيء سيسير كما هو مخطط. قد يكون الخادم الخارجي معطلاً، أو قد ترسل بيانات غير صحيحة، أو قد تنتهي صلاحية المفتاح.

### رموز الحالة HTTP التي تحتاج معرفتها

- **200**: النجاح المطلق
- **201**: تم الإنشاء بنجاح (POST عادةً)
- **400**: طلب خاطئ من جانبك (تحقق من صيغة البيانات)
- **401**: غير مصرح (المفتاح خاطئ أو منتهي الصلاحية)
- **403**: مرفوع الوصول (المفتاح صحيح لكن ليس لديك صلاحية هذا الإجراء)
- **404**: غير موجود (السجل الذي تبحث عنه لا وجود له)
- **500**: خطأ من جانب الخادم (انتظر قليلاً وحاول مجدداً)

عند كتابة وكيل أوبن كلاو، يجب أن تعطيه تعليمات واضحة لمعالجة هذه السيناريوهات:

```json
{
  "instruction": "إذا حصلت على رمز خطأ 404، أخبر المستخدم أن السجل غير موجود. إذا حصلت على 500، اطلب منه المحاولة لاحقاً. إذا حصلت على 401، هذا يعني مشكلة في المصادقة وأخبرني فوراً."
}
```

## سيناريو تطبيقي: متجر أثاث يتكامل مع نظام إدارة المخزون

### الحالة

دار الأثاث "الراحة الفاخرة" تريد وكيل ذكي يعمل على دردشتهم. العميل يسأل: "هل الكرسي الأحمر من طراز X متوفر؟" والوكيل يجب أن يفتش نظام المخزون الفعلي ويرد برقم دقيق في الحال.

### الحل خطوة بخطوة

**الخطوة 1: تحضير API الخاص بالمخزون**

فريق تقنية المتجر أعطاك رابط API الخاص بهم:

```
https://inventory.alrahah.com/api/v1/products
```

ويتطلب Token:

```
Authorization: Bearer sk_live_xyz123...
```

**الخطوة 2: كتابة دالة في أوبن كلاو للاتصال بالـ API**

```python
import requests
import os

def check_product_stock(product_id: str, color: str) -> dict:
    """جلب معلومات المخزون من نظام الراحة الفاخرة"""
    
    api_key = os.getenv("INVENTORY_API_KEY")
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json"
    }
    
    params = {
        "product_id": product_id,
        "color": color
    }
    
    try:
        response = requests.get(
            "https://inventory.alrahah.com/api/v1/products",
            headers=headers,
            params=params,
            timeout=5
        )
        
        if response.status_code == 200:
            data = response.json()
            return {
                "success": True,
                "stock": data.get("quantity", 0),
                "price": data.get("price"),
                "last_updated": data.get("updated_at")
            }
        elif response.status_code == 404:
            return {"success": False, "error": "المنتج غير موجود في النظام"}
        elif response.status_code == 401:
            return {"success": False, "error": "مشكلة في المصادقة"}
        else:
            return {"success": False, "error": f"خطأ {response.status_code}"}
    
    except requests.exceptions.Timeout:
        return {"success": False, "error": "النظام بطيء جداً الآن، حاول لاحقاً"}
    except Exception as e:
        return {"success": False, "error": str(e)}
```

## أفضل الممارسات عند بناء التكاملات

### 1. تصميم الطلبات بكفاءة

لا تطلب أكثر مما تحتاج. إذا كان API يقدم 50 حقل لكن تحتاج 3 فقط، اطلب تلك الثلاثة فقط باستخدام معاملات التصفية.

### 2. أضف مهلة زمنية (Timeout)

إذا انتظر الوكيل 10 دقائق لرد من API بطيء، سيكون تجربة المستخدم كارثة. حدد مهلة معقولة، 5 ثوان عادةً كافية.

### 3. تسجيل العمليات (Logging)

كل طلب تُرسله يجب أن يترك بصمة. هذا يساعدك في تتبع الأخطاء لاحقاً:

```python
import logging

logger = logging.getLogger("openclaw_api")
logger.info(f"الطلب إلى {url} مع المعاملات {params}")
logger.error(f"الفشل: {response.status_code}")
```

### 4. اختبر مع بيانات حقيقية

لا تختبر في بيئة الإنتاج. اطلب من الطرف الآخر بيئة اختبار (Sandbox) بتوفير بيانات وهمية.

للمزيد حول بناء وكلاء متقدمة، اطلع على [اختيار النموذج المناسب في أوبن كلاو](/blog/openclaw-choosing-right-model-beginners-arabic) لفهم أيهما أنسب لحالتك.

## معالجة المعدلات والحدود (Rate Limiting)

معظم الخدمات لا تسمح لك بإرسال عدد غير محدود من الطلبات. قد تقول: "500 طلب في الساعة فقط." إذا تجاوزتها، ستُحظر.

للتعامل مع هذا:

```python
import time
from functools import wraps

def rate_limit(max_calls=10, time_window=60):
    """تحديد سرعة الطلبات"""
    calls = []
    
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            now = time.time()
            calls[:] = [c for c in calls if c > now - time_window]
            
            if len(calls) >= max_calls:
                wait_time = time_window - (now - calls[0])
                time.sleep(wait_time)
            
            calls.append(now)
            return func(*args, **kwargs)
        return wrapper
    return decorator

@rate_limit(max_calls=100, time_window=3600)  # 100 طلب كل ساعة
def call_external_api():
    # كودك هنا
    pass
```

## تحسين سرعة الاستجابة مع Caching

إذا كان الكثير من المستخدمين يسألون عن نفس المنتج مرات متتالية، لماذا نطلب من الـ API نفس البيانات كل مرة؟ استخدم ذاكرة تخزين مؤقت.

```python
from functools import lru_cache
import time

@lru_cache(maxsize=128)
def get_product_cached(product_id: str):
    """جلب المنتج مع تخزين مؤقت"""
    return check_product_stock(product_id, "")
```

## الأمان: نقاط يجب أن تحافظ عليها

### تجنب حقن البيانات (Injection Attacks)

عندما تأخذ مدخلات المستخدم، تحقق منها قبل إرسالها للـ API:

```python
from urllib.parse import quote

user_input = request.args.get("search")
# تنظيف المدخلات
user_input = quote(user_input, safe='')  # فقط أحرف آمنة

# ثم استخدمها
url = f"https://api.example.com/search?q={user_input}"
```

### استخدام HTTPS فقط

أي اتصال يتضمن بيانات حساسة يجب أن يكون عبر HTTPS وليس HTTP العادي. تحقق دائماً من الشهادة.

### أوقات انتهاء الصلاحية

عرّف الـ Tokens لديك مع فترة انتهاء صلاحية قصيرة (ساعة أو يومين)، ثم عدّلها تلقائياً.

## الأسئلة الشائعة

### سؤال 1: كيف أختبر الـ API قبل ربطه مع الوكيل؟

**الجواب:** استخدم أداة مثل Postman أو curl من سطر الأوامر. أرسل طلب GET أو POST مباشرة برفقة مفاتيحك، وشاهد الرد. تأكد من الرموز والبيانات قبل كتابة الكود الفعلي. هذا يوفر عليك ساعات من البحث عن الأخطاء لاحقاً.

### سؤال 2: ماذا لو كان الـ API يتطلب صلاحيات معقدة (OAuth)؟

**الجواب:** OAuth معقد لكنه الخيار الأصح للأمان. أوبن كلاو توفر مكتبات تساعدك في التعامل معه. ستحتاج إلى تطبيق "مسار التدفق" الذي يسمح للمستخدم بالموافقة على الوصول مرة واحدة، ثم احفظ Token الناتج. للتطبيقات البسيطة، API Key كافية.

### سؤال 3: هل هناك حد لعدد الـ APIs التي يمكن أن يستخدمها الوكيل الواحد؟

**الجواب:** تقنياً لا حد، لكن عملياً كل API إضافية تزيد التعقيد والأخطاء المحتملة. ابدأ بـ API واحدة أو اثنتين، ثم أضف حسب الحاجة. كل API تضيفها يجب أن تحسّن التجربة بشكل واضح للمستخدم.

### سؤال 4: ماذا أفعل إذا كان الـ API بطيء جداً؟

**الجواب:** أولاً، تحقق أن المشكلة ليست من جانبك (سرعة الإنترنت أو خادمك). ثانياً، أضف caching كما شرحنا. ثالثاً، اطلب من الطرف الآخر تحسين الأداء أو ابحث عن بديل أسرع. أخيراً، أخبر الوكيل أن يُخبر المستخدم بأن الـ API بطيء ويحتاج وقتاً أطول، بدلاً من التأخير الصامت.

### سؤال 5: هل يمكنني استخدام أوبن كلاو مع APIs لا تملكها أنا؟

**الجواب:** نعم تماماً. هذا جزء من قوة أوبن كلاو. طالما لديك مفتاح API صحيح من الطرف الآخر (مثل Google Maps API أو خدمة بريد إلكترونية)، يمكنك تربطها. تأكد فقط أن اتفقت قانونياً مع مزود الخدمة على استخدامك لديهم برموز API مختلفة إذا كان هناك عدة حسابات.

## خاتمة

دمج REST APIs مع أوبن كلاو ليس سحراً معقداً. إنه مزيج من الفهم الأساسي لـ HTTP وتطبيق حذر للممارسات الآمنة. ابدأ بـ API واحدة، اختبرها بعناية، ثم وسّع تدريجياً.

المفتاح أن تذكر أن كل تكامل يجب أن يحل مشكلة حقيقية للمستخدم. API الفاخرة التي لا تضيف قيمة ستكون مصدر صداع فقط.

**الآن حان وقت الفعل:** اختر API واحدة من أنظمتك، اتبع الخطوات في هذا المقال، واختبرها بسرعة. إذا واجهتك مشكلة، ابحث عن رموز الخطأ المحددة بدلاً من اليأس. المجتمع العربي حول أوبن كلاو ينمو، والإجابات قريبة.

للمزيد حول أتمتة عمليات متقدمة، شاهد [أتمتة تيليغرام مع أوبن كلاو](/blog/2026-02-22-telegram-automation-guide) أو ابدأ مباشرة مع [openclaw.ai](https://openclaw.ai) لتستكشف كل الإمكانيات.
